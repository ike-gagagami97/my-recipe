## 2. 機能仕様の整理（テストベース）

| 参照 | パス / 節 | メモ |
| --- | --- | --- |
| feature doc | `docs/product/features/recipe-favorite.md` §1〜7・§8（承認済み判断） | 受け入れ契約の正本 |
| vision | `docs/product/vision.md` | P2 ポスト MVP・着手中。認証必須・自分のレシピのみ |
| 実装後差分 | 一覧 `/recipes`・詳細 `/recipes/[id]` にトグルとフィルタを追加。migration `20261005000000_add_recipes_is_favorite.sql`。E2E `tests/e2e/recipe-favorite.spec.ts`（コアパス）。L1 suite 71 passed（実装者報告） | 契約と矛盾する UI は観測せず。手順を出荷ラベル／URL に合わせた |

仕様メモ（画面で観察できることだけ・実装後観察）:

- 詳細（`/recipes/[id]`）: タイトル直下のボタン。表示ラベル「お気に入り」／「お気に入り中」。`aria-label`「お気に入りにする」／「お気に入りを外す」。`aria-pressed` false／true。星アイコン＋テキスト
- 一覧（`/recipes`）各行: コンパクトな星アイコンボタン（テキストなし）。同じ `aria-label`／`aria-pressed`。列ヘッダーは sr-only「お気に入り」
- 一覧フィルタ: 所要時間プルダウン横のチェックボックス。可視ラベル「お気に入りのみ」、`aria-label`「お気に入りのみ」。選択即時反映（専用送信ボタンなし）。`push` 時に `page` クエリを削除 → 1 ページ目へ
- URL: 「お気に入りのみ」ON で `favorite=1`。OFF で当該クエリ削除。リロード後もチェック状態と結果が残る
- AND: `favorite=1` と既存の `keyword`・`cooking_time`（例: `under10` / `10to20` / `20to30` / `over30`）が同時に効く
- 0 件時: 「条件に一致するレシピがありません。」。キーワード・所要時間・「お気に入りのみ」は操作可能なまま
- 永続化: 列 `recipes.is_favorite`（boolean NOT NULL DEFAULT false）。付け外しのみでは `updated_at` をバンプしない（migration の trigger・§8 Q4）
- 保存失敗時: `role="alert"` でエラー文言（例: 「お気に入りの保存に失敗しました。もう一度お試しください。」）。ローカルでは失敗注入の信頼できる経路なし → TC-10 は意図的スキップ（§7）
- 未ログイン: `/recipes`・`/recipes/[id]` 直開きでログインへ。他ユーザー／不正 ID は「レシピが見つかりません」（お気に入り操作なし）
- §4 不在: お気に入り専用 URL／画面なし。追加・編集フォームにお気に入り設定なし。フォルダ・お気に入り優先ソートなし

## 3. テスト計画

### 3.1 テスト目的

- 受け入れ契約（feature §5 / §6）の充足確認（詳細・一覧トグル、絞り込み、永続化、空状態、未ログイン）
- §7 の保存失敗・他ユーザー／not-found、§4 スコープ外 UI の抜け検知
- 既存のタイトル検索・所要時間・ソート・ページネーションの回帰確認
- 権限境界（自分のレシピのみ見える・触れられる）の確認

### 3.2 テスト観点（perspectives）

| 観点 | 対象 | 理由 / メモ |
| --- | --- | --- |
| 機能（正常系） | 対象 | §5 の付け外し・絞り込み・AND・URL 永続・ページリセットが主価値 |
| 異常・空・バリデーション | 対象 | §7: 0 件案内、保存失敗時の表示整合（失敗注入は §7 スキップ） |
| 権限・セッション・RLS | 対象 | 未ログイン、他ユーザー／存在しないレシピ、自分のレシピのみ |
| 回帰（隣接画面） | 対象 | 一覧の検索・所要時間・ソート・ページネーション、詳細・ログイン |
| 表示・レスポンシブ | 対象 | §6 確認メモ「モバイル幅も見る」。一覧行コントロールとフィルタが狭幅でも操作可能か |
| スコープ外の不在 | 対象 | §4 の専用画面・フォーム設定・フォルダ／優先ソートが出ないこと |

### 3.3 範囲とレベル

| 項目 | 内容 |
| --- | --- |
| In（この設計でカバーする） | 詳細／一覧の ON/OFF と画面上の状態、永続化（リロード）、「お気に入りのみ」フィルタ（単独・AND・0 件・ページリセット・URL 永続）、保存失敗の見え方（再現時）、未ログイン／他ユーザー・not-found、§4 不在、既存一覧操作の回帰、モバイル幅の操作可否 |
| Out（意図的にやらない） | フォルダ／複数リスト／ラベルの仕様検証（非スコープ）、共有・公開、画像、検索対象拡張・タグ、migration の SQL 単体レビュー（`db-security-auditor` 側）、更新日時の DB 直接照合（画面上の更新日時表示で確認）、ローカルでの保存失敗注入（§7） |
| 想定 Test level | **L0 + L1 + L2 + L4**（L3: env／デプロイ変更が無ければ不要） |
| 変更タイプ（ルール表） | **新規画面・新規フロー**（既存画面への新規フロー）+ **migration / DB 書込**（列追加）。重い方を採用 → L0 + L2 + L4。該当 E2E あり → L1 も必須セットに含める |
