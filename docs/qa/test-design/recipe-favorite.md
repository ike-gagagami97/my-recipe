## 2. 機能仕様の整理（テストベース）

| 参照 | パス / 節 | メモ |
| --- | --- | --- |
| feature doc | `docs/product/features/recipe-favorite.md` §1〜7・§8（承認済み判断） | 受け入れ契約の正本 |
| vision | `docs/product/vision.md` | P2 ポスト MVP・着手中。認証必須・自分のレシピのみ |
| 実装後差分 | なし（draft・未実装前提） | delta 時に画面ラベル・URL クエリ名・永続化の見え方を具体化する |

仕様メモ（画面で観察できることだけ）:

- 詳細（`/recipes/[id]`）でお気に入りを ON / OFF でき、操作後の状態が画面上で分かる
- 一覧（`/recipes`）の各行でお気に入りを ON / OFF でき、行上で状態が分かる（星・ブックマーク等のコントロール。絵文字は使わない — §8 Q3）
- 付け外しは詳細・一覧の両方（§8 Q1）。どちらで操作してもリロード後も同じ状態
- 一覧の所要時間プルダウン横に「お気に入りのみ」チェック（または同等トグル）。選択即時反映・専用ボタンなし（§8 Q2）
- 「お気に入りのみ」は既存のタイトル検索・所要時間と AND。結果 0 件時は「条件に一致するレシピがありません」系の案内。絞り込み UI は残る
- 「お気に入りのみ」の ON/OFF で 1 ページ目に戻る（既存フィルタ変更時と同じ）
- 「お気に入りのみ」の選択は URL クエリで持ち、リロード後も残る（§8 Q6）
- お気に入りの付け外しで更新日時は変わらない（§8 Q4）。粒度はレシピごとに ON/OFF 1 つ（§8 Q5）
- 保存失敗時はエラーが分かり、画面上の ON/OFF 表示が実際の状態と食い違ったままにならない
- 未ログインで一覧・詳細 URL を直接開くとログインへリダイレクト。他ユーザー／存在しないレシピは既存の「見つかりません」扱い、お気に入り操作は出ない
- お気に入り専用の別画面・別 URL、追加／編集フォームからのお気に入り設定、フォルダ分け・お気に入り優先ソートは出ない（§4）

## 3. テスト計画

### 3.1 テスト目的

- 受け入れ契約（feature §5 / §6）の充足確認（詳細・一覧トグル、絞り込み、永続化、空状態、未ログイン）
- §7 の保存失敗・他ユーザー／not-found、§4 スコープ外 UI の抜け検知
- 既存のタイトル検索・所要時間・ソート・ページネーションの回帰確認
- 権限境界（自分のレシピのみ見える・触れられる）の確認

### 3.2 テスト観点（perspectives）

| 観点 | 対象 | 理由 / メモ |
| --- | --- | --- |
| 機能（正常系） | 対象 | §5 の付け外し・絞り込み・AND・URL 永続・ページリセットが主価値 |
| 異常・空・バリデーション | 対象 | §7: 0 件案内、保存失敗時の表示整合 |
| 権限・セッション・RLS | 対象 | 未ログイン、他ユーザー／存在しないレシピ、自分のレシピのみ |
| 回帰（隣接画面） | 対象 | 一覧の検索・所要時間・ソート・ページネーション、詳細・ログイン |
| 表示・レスポンシブ | 対象 | §6 確認メモ「モバイル幅も見る」。一覧行コントロールとフィルタが狭幅でも操作可能か |
| スコープ外の不在 | 対象 | §4 の専用画面・フォーム設定・フォルダ／優先ソートが出ないこと |

### 3.3 範囲とレベル

| 項目 | 内容 |
| --- | --- |
| In（この設計でカバーする） | 詳細／一覧の ON/OFF と画面上の状態、永続化（リロード）、「お気に入りのみ」フィルタ（単独・AND・0 件・ページリセット・URL 永続）、保存失敗の見え方、未ログイン／他ユーザー・not-found、§4 不在、既存一覧操作の回帰、モバイル幅の操作可否 |
| Out（意図的にやらない） | フォルダ／複数リスト／ラベルの仕様検証（非スコープ）、共有・公開、画像、検索対象拡張・タグ、migration の SQL 単体レビュー（`db-security-auditor` 側）、E2E へのケース移植（L1 は既存 spec 回帰のみ・任意 follow-up）、更新日時の DB 直接照合（画面上の更新日時表示で確認） |
| 想定 Test level | **L0 + L2 + L4**（L1: 一覧・詳細・auth の既存 E2E があれば実行。L3: env／デプロイ変更が無ければ不要） |
| 変更タイプ（ルール表） | **新規画面・新規フロー**（既存画面への新規フロー）+ **migration / DB 書込**（列追加）。重い方を採用 → L0 + L2 + L4 |

| L1（Playwright）新規ケース | 本設計の L2 移植は必須ではない。既存一覧・詳細・auth E2E の回帰は別途 | 該当 E2E があれば L1 実行。新規 E2E は L4 後または ⑤ で検討 |
| L3 | env／デプロイ変更が無ければルール上不要 | Preview 固有リスクが出たら L3 を追加 |
| migration / RLS / GRANT の静的監査 | 本設計の画面観察外 | 実装 PR で `db-security-auditor`・`code-reviewer` |
| 二重トグル競合・連続クリック | §5 に明示なし。優先度を上げず draft では未採択 | 実装で楽観更新するなら delta で条件追加を検討 |
