## 1. ひとことで言うと（必須）

新しいレシピをフォームから入力して保存し、自分の一覧・詳細ですぐ確認できる。

## 2. だれの・どんな場面か（必須）

| 項目 | 内容 |
| --- | --- |
| だれ | 自分用にレシピを溜めたい個人 |
| ユーザー課題 | 作った料理や見つけたレシピをメモやスクショに残しても後で探せない。アプリには一覧・詳細があるのに、画面から新しいレシピを入れられない |
| 提供価値 | ブラウザだけでタイトル・材料・手順などを入力して保存でき、保存直後に自分のレシピとして一覧・詳細で見られる |
| 使う場面 | 料理が終わった直後に記録するとき、ネットや本で見つけたレシピを自分用に写すとき、買い物前に材料を先に書いておくとき |

## 3. できること（必須）

- レシピ一覧から「レシピを追加」で追加画面（`/recipes/new`）を開ける
- レシピが0件のときも、空の案内と一緒に追加画面への導線が見える
- 追加画面でタイトル・所要時間・材料・手順・メモを入力できる
- タイトルを入れて保存すると、新しいレシピとして保存される
- 保存後は、そのレシピの詳細画面が開く
- 材料・手順は複数行で入力でき、保存後の詳細では1行1項目／1行1ステップとして読める
- 所要時間・材料・手順・メモは空のまま保存できる
- タイトルが空のまま保存しようとすると、エラーが出て保存されない
- 「キャンセル」で一覧に戻れる（保存はされない）
- 未ログインで追加画面を直接開くとログイン画面にリダイレクトされる

## 4. やらないこと（必須）

- レシピの編集・削除、および詳細画面への編集／削除ボタン（[#7](https://github.com/ike-gagagami97/my-recipe/issues/7) / 将来の feature doc）
- 画像アップロード（vision 非スコープ）
- タグ・カテゴリ管理
- 下書き・自動保存・途中保存
- 材料・手順の構造化（分量を別カラムにする等）。改行区切りの複数行テキストとする（詳細と同方針）
- 他ユーザーへの共有・公開設定
- サインアップ画面（既存どおり Dashboard 手動作成）

## 5. 操作の流れ（必須・Gherkin）

```gherkin
Feature: レシピ追加
  フォームから新しいレシピを保存し、自分の詳細で確認できる

  Scenario: 一覧から追加画面を開く
    Given ログイン済みである
    When レシピ一覧で「レシピを追加」をクリックする
    Then レシピ追加画面が開く
    And タイトル・所要時間・材料・手順・メモの入力欄が見える

  Scenario: 0件の一覧からも追加画面へ行ける
    Given ログイン済みで、自分のレシピが0件である
    When レシピ一覧を開く
    Then まだレシピがないことが分かる案内が見える
    And 「レシピを追加」の導線が見える

  Scenario: 必須項目を入れて保存できる
    Given ログイン済みで、追加画面を開いている
    When タイトルに「テストカレー」と入力する
    And 所要時間に「30」と入力する
    And 材料に複数行で材料を入力する
    And 手順に複数行で手順を入力する
    And メモに一言入力する
    And 「保存」を押す
    Then そのレシピの詳細画面が開く
    And 入力したタイトル・所要時間・材料・手順・メモが見える

  Scenario: タイトル以外が空でも保存できる
    Given ログイン済みで、追加画面を開いている
    When タイトルだけ入力して「保存」を押す
    Then そのレシピの詳細画面が開く
    And 材料・手順・メモは未入力であることが分かる案内が出る
    And 所要時間は未設定であることが分かる表示になる

  Scenario: タイトルが空だと保存できない
    Given ログイン済みで、追加画面を開いている
    When タイトルを空のまま「保存」を押す
    Then 追加画面に留まる
    And タイトルが必要であることが分かるエラーが見える
    And 新しいレシピは一覧に増えない

  Scenario: タイトルが空白のみだと保存できない
    Given ログイン済みで、追加画面を開いている
    When タイトルにスペースだけ入力して「保存」を押す
    Then 追加画面に留まる
    And タイトルが必要であることが分かるエラーが見える

  Scenario: 所要時間が不正だと保存できない
    Given ログイン済みで、追加画面を開いている
    When タイトルを入力する
    And 所要時間に「0」を入力して「保存」を押す
    Then 追加画面に留まる
    And 所要時間の直し方が分かるエラーが見える

  Scenario: キャンセルで一覧に戻る
    Given ログイン済みで、追加画面を開いている
    And タイトルなど何か入力している
    When 「キャンセル」をクリックする
    Then レシピ一覧画面に戻る
    And 入力内容は保存されていない

  Scenario: 保存したレシピが一覧に出る
    Given ログイン済みである
    When 追加画面でタイトル付きのレシピを保存する
    And 詳細画面から一覧に戻る
    Then 一覧にそのレシピのタイトルが見える

  Scenario: 未ログインで追加画面を直接開く
    Given ログインしていない
    When レシピ追加画面の URL を直接開く
    Then ログイン画面にリダイレクトされる
    And 追加フォームは表示されない
```

## 6. 受け入れ条件（必須）

### 合格条件

- [ ] §5 の各 Scenario を Preview またはローカルで確認した
- [ ] 一覧に「レシピを追加」があり、クリックで `/recipes/new` に遷移する
- [ ] レシピ0件の一覧でも「レシピを追加」の導線が見える
- [ ] 追加画面にタイトル・所要時間・材料・手順・メモの入力欄がある
- [ ] タイトルを入れて保存すると、そのレシピの詳細画面（`/recipes/[id]`）に遷移する
- [ ] 詳細画面に、入力したタイトル・所要時間・材料・手順・メモが表示される
- [ ] 材料は1行1項目の箇条書き、手順は1から始まる番号付きで、入力した行順に表示される（詳細と同方針）
- [ ] タイトル以外を空にして保存した場合、詳細で所要時間は未設定と分かり、材料は「材料は登録されていません」、手順は「手順は登録されていません」、メモは「メモはありません」など、未入力であることが欄を残したまま分かる
- [ ] タイトルが空、または空白のみのとき保存されず、追加画面にエラーが出る
- [ ] 所要時間に 0・負数・小数・文字を入れて保存しようとすると保存されず、所要時間のエラーが見える（空のままなら保存可）
- [ ] 「キャンセル」で一覧に戻り、その操作ではレシピが増えない
- [ ] 保存したレシピが一覧に表示され、他ユーザーの一覧には出ない（自分のレシピとして見える）
- [ ] 保存直後の詳細で、更新日時が日本時間（JST）で見える（今年は `MM/DD HH:mm`、昨年以前は `YYYY/MM/DD HH:mm`。詳細 feature と同じ）
- [ ] 保存に失敗したとき、追加画面にエラーが見え、真っ白や無限ロードにならない。可能なら入力内容が残る
- [ ] 未ログインで `/recipes/new` を直接開くとログイン画面にリダイレクトされる
- [ ] 追加画面に編集・削除・画像アップロード・タグ入力は無い（§4）
- [ ] モバイル幅（375px 相当）で横スクロールなしにフォームを操作できる
- [ ] 一覧の検索・絞り込み・ソート・ページネーション、および既存の詳細表示が従来どおり動く（回帰）

### 確認メモ（環境・範囲）

- 確認環境: ローカル / Preview
- 端末: モバイル幅も見る
- 回帰で触る画面: レシピ一覧（`/recipes`）、レシピ詳細（`/recipes/[id]`）、ログイン（`/login`）
- その他メモ:
  - サインアップ画面が無いため、L4 前に確認済みユーザー（A/B）を用意する
  - L4 では「タイトル＋全項目入力」「タイトルのみ」「タイトル空で保存失敗」「所要時間不正」「キャンセル」「0件一覧からの追加」を必ず通す
  - 他ユーザー非表示: ユーザーAで新規保存 → ログアウト → 確認済みのユーザーBでログイン → 一覧にAがさっき保存したタイトルが出ないこと

## 7. 空・エラー・例外（任意）

| 場面 | 期待する見え方・挙動 |
| --- | --- |
| タイトル未入力・空白のみ | 保存されない。タイトルが必要だと分かるエラー。入力済みの他項目は消えない |
| 所要時間が不正（負数・小数・文字・0） | 保存されない。追加画面に所要時間の直し方が分かるエラーが出る。入力済みの他項目は消えない。未入力（空）だけが「未設定」として許可される |
| 保存に失敗（通信・DB エラー） | 追加画面にエラーメッセージ。真っ白・無限ロードにしない。入力内容はできるだけ残す |
| 未ログイン | ログイン画面へリダイレクト（既存の認証フローに委ねる） |
| 材料・手順の空行 | 保存は可。詳細表示では空行を除いて整列する（詳細と同方針） |

## 8. オープンクエスチョン（任意）

承認時に Yes/No してほしい提案。未回答のまま「実装中」にはしない。

- [ ] Q1. フォームの項目は？ → **提案: タイトル・所要時間・材料・手順・メモ**（詳細に出る項目と揃える。作成日時は入力しない）
- [ ] Q2. 必須はどれか？ → **提案: タイトルのみ必須**（空白のみ不可）。所要時間・材料・手順・メモは任意
- [ ] Q3. 保存後の遷移先は？ → **提案: 保存したレシピの詳細画面**（すぐ内容を確認できる）
- [ ] Q4. キャンセルの行き先は？ → **提案: レシピ一覧**（クエリなしの `/recipes` でよい）
- [ ] Q5. 0件一覧に追加導線を出すか？ → **提案: 出す**（一覧 feature 時点では出さなかったが、追加 feature で追加する）
- [ ] Q6. 所要時間の入力 UI と許可値は？ → **提案: 分単位の整数入力（任意）。空＝未設定。1以上の整数のみ可（0・小数・文字・負数は不可でエラー）**
- [ ] Q7. 材料・手順の持ち方は？ → **提案: 詳細と同じく改行区切りの複数行テキスト**（構造化はしない）

## 付録（任意・空欄のままでよい）

### 実装メモ（エージェント用）

- ルート: `src/app/recipes/new/page.tsx`（フォームは Server Action 想定。`"use client"` は最小限）
- 一覧: 「レシピを追加」リンク（0件時の空状態にも同じ導線）
- DB: 既存 `public.recipes` を利用。列は既に揃っている（`title` / `cooking_time_minutes` / `ingredients` / `steps` / `notes`）。`insert` の RLS policy と `grant insert` は既存 migration 済み。新規テーブルや列追加は原則不要
- `user_id` はサーバー側で `auth.getUser()` の ID をセット（クライアントから改ざんさせない）
- バリデーション: タイトル trim 後に空ならエラー。所要時間は空＝未設定、それ以外は1以上の整数のみ（§7 / §8 Q6）
- 使う skills: `recipe-feature`, `verify-frontend-change`（migration が必要になった場合のみ `supabase-migration`）
- テストレベル（想定）: 新規画面・新規フロー → **L0 + L2 + L4**。既存 E2E（auth / list / detail）に触るため **L1 も実施**。新規 E2E spec（`tests/e2e/`）を §5 向けに追加。L3 は env 変更が無ければ不要。権限の「書ける」拡大はあるが insert policy は既存のため新規 RLS 変更が無ければ H3「権限拡大」の新規ポリシー追加には当たらない——ポリシーを触ったら L4 必須のまま + `db-security-auditor`
- migration / RLS を触る場合は `code-reviewer` と `db-security-auditor` を実装 PR で実行
