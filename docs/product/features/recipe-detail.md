## 1. ひとことで言うと（必須）

一覧で見つけたレシピを開いて、材料・手順・メモまで含めた中身をひと画面で確認できる。

## 2. だれの・どんな場面か（必須）

| 項目 | 内容 |
| --- | --- |
| だれ | 自分用にレシピを溜めたい個人 |
| ユーザー課題 | 一覧ではタイトルと所要時間しか分からず、「実際に何を買って、どう作るのか」を確認できない |
| 提供価値 | レシピを1つ開けば、材料と手順が上から順に読める。買い物中や調理中にスマホで開いてそのまま作れる |
| 使う場面 | 買い物前に材料を確認するとき、キッチンで手順を見ながら調理するとき |

## 3. できること（必須）

- レシピ一覧でレシピのタイトルをクリックすると、そのレシピの詳細画面（`/recipes/[id]`）が開く
- 詳細画面でタイトル・所要時間・材料・手順・メモ・更新日時を確認できる
- 詳細画面の「編集」から編集画面（`/recipes/[id]/edit`）を開ける（[#25](https://github.com/ike-gagagami97/my-recipe/issues/25)）
- 材料は1行1項目の箇条書きで読める
- 手順は1行1ステップの番号付きリストで読める
- 材料・手順・メモが未入力のレシピは、その欄が未入力であることが分かる
- 「一覧に戻る」リンクで、直前に見ていた一覧（検索・絞り込み・ソート・ページの状態）に戻れる
- モバイル幅でも縦スクロールだけで全項目を読める

## 4. やらないこと（必須）

- レシピの追加（[#6](https://github.com/ike-gagagami97/my-recipe/issues/6)）
- レシピの削除、および詳細画面への削除ボタンの設置（[#26](https://github.com/ike-gagagami97/my-recipe/issues/26)）
- 画像・サムネイルの表示
- コメント・いいね・共有などのソーシャル機能
- 印刷用レイアウト、材料の分量スケーリング（人数変更）、チェックボックス付き買い物リスト
- 詳細画面から次／前のレシピへの移動
## 5. 操作の流れ（必須・Gherkin）

```gherkin
Feature: レシピ詳細
  一覧で選んだレシピの材料・手順・メモをひと画面で確認できる

  Scenario: 一覧からレシピ詳細を開く
    Given ログイン済みで、自分のレシピが1件以上ある
    When レシピ一覧でレシピのタイトルをクリックする
    Then そのレシピの詳細画面が開く
    And タイトル・所要時間・材料・手順・メモ・更新日時が見える

  Scenario: 材料と手順が読みやすく並ぶ
    Given 材料と手順が複数行入力されたレシピがある
    When そのレシピの詳細画面を開く
    Then 材料が1行1項目の箇条書きで表示される
    And 手順が1から始まる番号付きで、入力順に表示される

  Scenario: 未入力の項目があるレシピを開く
    Given 材料・手順・メモが未入力のレシピがある
    When そのレシピの詳細画面を開く
    Then タイトルは表示される
    And 材料・手順・メモの欄は未入力であることが分かる案内が出る
    And 画面が空白や崩れた見た目にはならない

  Scenario: 所要時間が未設定のレシピを開く
    Given 所要時間が未設定のレシピがある
    When そのレシピの詳細画面を開く
    Then 所要時間が未設定であることが分かる表示になる

  Scenario: 一覧に戻る
    Given レシピ詳細画面を開いている
    When 「一覧に戻る」リンクをクリックする
    Then レシピ一覧画面に戻る
    And 詳細を開く前の検索キーワード・絞り込み・並び順・ページがそのまま復元されている

  Scenario: 未ログインで詳細画面を直接開く
    Given ログインしていない
    When レシピ詳細画面の URL を直接開く
    Then ログイン画面にリダイレクトされる
    And レシピの内容は一切表示されない

  Scenario: 他ユーザーのレシピを直接開く
    Given ログイン済みで、他ユーザーのレシピの URL を知っている
    When その URL を直接開く
    Then レシピが見つからない旨の画面が表示される
    And 他ユーザーのレシピの内容は一切表示されない

  Scenario: 存在しないレシピを開く
    Given 存在しないレシピの URL を開く
    When 画面が表示される
    Then レシピが見つからない旨の画面が表示される
    And 一覧に戻る導線がある
```

## 7. 空・エラー・例外（任意）

| 場面 | 期待する見え方・挙動 |
| --- | --- |
| 材料が未入力 | 「材料は登録されていません」などの案内。見出し自体は残す |
| 手順が未入力 | 「手順は登録されていません」などの案内。見出し自体は残す |
| メモが未入力 | 「メモはありません」などの案内。見出し自体は残す |
| 所要時間が未設定 | 一覧と揃えて未設定と分かる表示にする |
| 存在しない ID・他ユーザーの ID・不正な形式の ID | すべて同じ「レシピが見つかりません」画面（存在の有無を区別して見せない）。一覧に戻るリンクを置く |
| 取得に失敗（通信・DB エラー） | エラーメッセージを表示（真っ白・無限ロードにしない） |
| 未ログイン | ログイン画面へリダイレクト（既存の認証フローに委ねる） |

## 付録（任意・空欄のままでよい）

### 実装メモ（エージェント用）

- ルート: `src/app/recipes/[id]/page.tsx`（Server Component。`params` は Next.js 16 で `Promise`）
- 見つからない場合: `notFound()` で `not-found.tsx` を出す（RLS により他ユーザー行は 0件で返るので自然に同じ扱いになる）
- DB: 既存 `public.recipes` に列追加の migration が必要（現状は `title` / `cooking_time_minutes` のみ）
  - `ingredients` text NULL（改行区切り）
  - `steps` text NULL（改行区切り）
  - `notes` text NULL
  - 既存行は NULL のまま。RLS ポリシー・GRANT は既存の `authenticated` 向け設定を流用（列追加のみで新規テーブルではない）
- 一覧側: タイトルセルを `next/link` に変更し、現在のクエリ文字列を詳細 URL に引き継ぐ（戻り先の復元用）
- 表示整形: 改行で分割 → 空行を除去 → `ul` / `ol` で描画（分割ロジックは `src/lib/` に置いて一覧・詳細で共有可能にする）
- 確認用データ: `supabase/qa/*.sql`（手動実行専用。`config.toml` の `[db.seed]` は `./seed.sql` しか読まないので `supabase db reset` では流れない）
- 使う skills: `recipe-feature`, `supabase-migration`, `verify-frontend-change`
- テストレベル（想定）: 新規画面・新規フロー + migration → **L0 + L2 + L4**（L3 は env 変更が無ければ不要）
- migration / RLS を含むため `code-reviewer` サブエージェントを実装 PR で実行する
