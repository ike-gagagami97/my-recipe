## 1. ひとことで言うと（必須）

よく作る／よく見るレシピをお気に入りに付け外しでき、一覧で「お気に入りのみ」に絞り込める。

## 2. だれの・どんな場面か（必須）

| 項目 | 内容 |
| --- | --- |
| だれ | 自分用にレシピを溜めたい個人 |
| ユーザー課題 | レシピが増えると、よく使うものが見つけにくく、キーワードや所要時間だけでは「いつもの候補」をすぐ出せない |
| 提供価値 | お気に入りを付けておけば、一覧の絞り込みでいつものレシピだけをすぐ出せる。リロード後も状態が残る |
| 使う場面 | 献立を考えるとき、よく作る定番だけを見たいとき、詳細を見ながら「これは定番だ」とマークするとき |

## 3. できること（必須）

- レシピ詳細で、そのレシピのお気に入りを ON / OFF できる
- レシピ一覧の各行で、そのレシピのお気に入りを ON / OFF できる
- 一覧でお気に入り状態（ON / OFF）が一目で分かる
- 一覧で「お気に入りのみ」に絞り込める
- 「お気に入りのみ」と既存のタイトル検索・所要時間絞り込みを同時に使える（AND）
- お気に入りの状態は保存され、リロード後も同じ状態で見える
- 自分のレシピのみお気に入り操作・表示できる（他ユーザーのレシピは触れない）

## 4. やらないこと（必須）

- お気に入りのフォルダ分け・複数リスト・ラベル分け
- 並び順の手動カスタム（ドラッグ並べ替え）・「お気に入り優先」ソートの追加
- 共有・公開・他ユーザーからのお気に入り
- お気に入り専用の別画面・別 URL
- レシピ追加・編集フォームからのお気に入り設定
- 画像アップロード（vision 非スコープ）
- レシピ検索対象の拡張（[#38](https://github.com/ike-gagagami97/my-recipe/issues/38)）
- タグ／カテゴリ（[#39](https://github.com/ike-gagagami97/my-recipe/issues/39)）

## 5. 操作の流れ（必須・Gherkin）

```gherkin
Feature: レシピお気に入り
  よく使うレシピをお気に入りにし、一覧で絞り込める

  Scenario: 詳細でお気に入りにする
    Given ログイン済みで、自分のレシピの詳細画面を開いている
    And そのレシピはお気に入りではない
    When お気に入りを ON にする操作をする
    Then そのレシピがお気に入りであることが画面上で分かる
    And ページを再読み込みしてもお気に入りのままである

  Scenario: 詳細でお気に入りを外す
    Given ログイン済みで、自分のお気に入りレシピの詳細画面を開いている
    When お気に入りを OFF にする操作をする
    Then そのレシピがお気に入りではないことが画面上で分かる
    And ページを再読み込みしてもお気に入りではない

  Scenario: 一覧行でお気に入りを付け外しできる
    Given ログイン済みで、レシピ一覧に自分のレシピが1件以上ある
    When あるレシピの行でお気に入りを ON にする
    Then その行がお気に入りであることが分かる
    And ページを再読み込みしてもその行はお気に入りのままである
    When 同じ行でお気に入りを OFF にする
    Then その行がお気に入りではないことが分かる
    And ページを再読み込みしてもお気に入りではない

  Scenario: お気に入りのみで絞り込める
    Given ログイン済みで、お気に入りのレシピとそうでないレシピがそれぞれ1件以上ある
    When 一覧で「お気に入りのみ」を選ぶ
    Then お気に入りのレシピだけが表示される
    And お気に入りではないレシピは表示されない

  Scenario: お気に入り絞り込みと既存の検索・所要時間を同時に使える
    Given ログイン済みで、タイトル・所要時間・お気に入り状態が異なるレシピが複数ある
    When 「お気に入りのみ」を選ぶ
    And タイトル検索と所要時間絞り込みを適用する
    Then お気に入り かつ キーワード一致 かつ 所要時間条件を満たすレシピのみ表示される

  Scenario: お気に入りのみの結果が0件のとき案内が出る
    Given ログイン済みで、お気に入りのレシピが1件もない
    When 一覧で「お気に入りのみ」を選ぶ
    Then 条件に一致するレシピがないことが分かる案内が見える
    And 絞り込み操作はそのまま使える

  Scenario: お気に入り絞り込みを変えると1ページ目に戻る
    Given ログイン済みで、お気に入りのレシピが11件以上あり、2ページ目を表示している
    When 「お気に入りのみ」を選ぶ
    Then 絞り込み結果の1ページ目が表示される

  Scenario: お気に入りのみの選択はリロード後も残る
    Given ログイン済みで、一覧で「お気に入りのみ」を選んでいる
    When ページを再読み込みする
    Then 「お気に入りのみ」が選ばれたままである
    And お気に入りのレシピだけが表示される

  Scenario: 未ログインではお気に入り操作できない
    Given ログインしていない
    When レシピ一覧または詳細の URL を直接開く
    Then ログイン画面にリダイレクトされる
    And お気に入り操作はできない
```

## 6. 受け入れ条件（必須）

### 合格条件

- [ ] §5 の各 Scenario を Preview またはローカルで確認した
- [ ] 詳細画面でお気に入りを ON / OFF でき、操作後の状態が画面上で分かる
- [ ] 一覧の各行でお気に入りを ON / OFF でき、行上で状態が分かる
- [ ] 一覧行・詳細のどちらで ON / OFF しても、ページを再読み込みすると同じ状態のままである（永続化）
- [ ] 一覧で「お気に入りのみ」を選ぶと、お気に入りのレシピだけが表示される
- [ ] 「お気に入りのみ」とタイトル検索・所要時間絞り込みは AND で同時に効く
- [ ] 「お気に入りのみ」の結果が0件のとき、既存の「条件に一致するレシピがありません」系の案内が出る（一覧が壊れた見た目にならない）
- [ ] 「お気に入りのみ」の ON / OFF でページが1ページ目に戻る（既存の検索・絞り込み変更時と同じ）
- [ ] 「お気に入りのみ」の選択はリロード後も残る（既存の検索・所要時間と同様に URL クエリで持つ）
- [ ] お気に入りの保存に失敗したとき、エラーが分かり、画面上の ON/OFF 表示が実際の状態と食い違ったままにならない
- [ ] 既存のタイトル検索・所要時間・ソート・ページネーションが従来どおり動く（回帰）
- [ ] ログイン済みユーザーの自分のレシピのみお気に入り操作・表示できる（他ユーザーのレシピは見えない・触れない）
- [ ] 未ログインでレシピ一覧または詳細の URL を直接開くとログイン画面にリダイレクトされ、お気に入り操作はできない

## 7. 空・エラー・例外（任意）

| 場面 | 期待する見え方・挙動 |
| --- | --- |
| お気に入り0件で「お気に入りのみ」 | 「条件に一致するレシピがありません」など。絞り込み UI は残す |
| お気に入りの保存に失敗 | エラーが分かり、画面上の ON/OFF 表示が実際の状態と食い違ったままにならない |
| 未ログイン | ログイン画面へリダイレクト（既存の認証フローに委ねる） |
| 他ユーザー・存在しないレシピ | 既存の「見つかりません」扱い。お気に入り操作は出ない |

## 付録（任意・空欄のままでよい）

### 実装メモ（エージェント用）

- 想定ルート: 既存 `/recipes`・`/recipes/[id]` を拡張（専用画面なし）
- データ: `recipes.is_favorite` boolean NOT NULL DEFAULT false（列名は実装時に確定可）
- RLS / GRANT: 既存の `authenticated` 向けポリシーを流用（列追加のみ）
- 一覧クエリ: 既存の検索・所要時間・ソート・ページネーションに `is_favorite = true` 条件を追加可能にする（URL クエリで状態を持てると戻りやすい）
- 使う skills: `recipe-feature`, `supabase-migration`, `verify-frontend-change`, `design-tests`, `run-tests`
- テストレベル（想定）: 既存画面への新規フロー + migration → **L0 + L2 + L4**（L3 は env 変更が無ければ不要）
- migration を含むため実装 PR で `code-reviewer` と `db-security-auditor` を実行する
