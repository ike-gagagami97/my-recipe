## 1. ひとことで言うと（必須）

不要になったレシピを詳細画面から削除でき、確認後に一覧から消える。

## 2. だれの・どんな場面か（必須）

| 項目 | 内容 |
| --- | --- |
| だれ | 自分用にレシピを溜めたい個人 |
| ユーザー課題 | 試してみて使わなくなったレシピや、入力ミスで作ったレシピが残り続け、一覧がごちゃごちゃになる。編集では消せない |
| 提供価値 | 詳細から「削除」を選び、確認すればレシピが完全に消え、一覧にも出なくなる |
| 使う場面 | 同じレシピを改良版に置き換えたあと旧版を消すとき、誤って追加したレシピを片付けるとき |

## 3. できること（必須）

- レシピ詳細から「削除」ボタンを押せる
- 「削除」を押すと、本当に消してよいか確認するダイアログが出る
- 確認ダイアログで「削除する」を選ぶと、そのレシピが完全に削除される
- 削除後はレシピ一覧（`/recipes`）に遷移し、削除したレシピのタイトルは一覧に表示されない
- 確認ダイアログで「キャンセル」を選ぶと、ダイアログが閉じ詳細画面に留まり、レシピは削除されない
- 未ログインで詳細 URL を開くとログイン画面にリダイレクトされる（削除ボタンは表示されない）
- 他ユーザーのレシピは削除できない（詳細画面自体が「見つかりません」になり、削除ボタンは出ない）

## 4. やらないこと（必須）

- 編集画面からの削除導線（削除は詳細画面のみ）
- 一覧行からの直接削除
- 一括削除
- 削除履歴・アーカイブ・ゴミ箱（物理削除のみ）
- 論理削除（`deleted_at` など）
- 削除の取り消し（Undo）
- 画像アップロード・タグ・共有など vision 非スコープの機能

## 5. 操作の流れ（必須・Gherkin）

```gherkin
Feature: レシピ削除
  不要なレシピを詳細から削除し、一覧から消える

  Scenario: 詳細からレシピを削除する
    Given ログイン済みで、自分のレシピの詳細画面を開いている
    When 「削除」をクリックする
    And 確認ダイアログで「削除する」を選ぶ
    Then レシピ一覧画面に遷移する
    And 削除したレシピのタイトルは一覧に表示されない

  Scenario: 確認ダイアログでキャンセルする
    Given ログイン済みで、自分のレシピの詳細画面を開いている
    When 「削除」をクリックする
    And 確認ダイアログで「キャンセル」を選ぶ
    Then 詳細画面に留まる
    And レシピのタイトルと内容がそのまま見える

  Scenario: 削除後に詳細 URL を直接開く
    Given ログイン済みで、自分のレシピを削除した
    When 削除したレシピの詳細 URL を直接開く
    Then レシピが見つからない旨の画面が表示される

  Scenario: 未ログインで詳細を開く
    Given ログインしていない
    When レシピ詳細画面の URL を直接開く
    Then ログイン画面にリダイレクトされる
    And 削除ボタンは表示されない

  Scenario: 他ユーザーのレシピは削除できない
    Given ログイン済みで、他ユーザーのレシピの詳細 URL を知っている
    When その URL を直接開く
    Then レシピが見つからない旨の画面が表示される
    And 削除ボタンは表示されない
```

## 6. 受け入れ条件（必須）

### 合格条件

- [ ] §5 の各 Scenario を Preview またはローカルで確認した
- [ ] 詳細画面に「削除」ボタンがある（「編集」の近く）
- [ ] 「削除」を押すと確認ダイアログが表示される
- [ ] 確認ダイアログで「削除する」を選ぶとレシピが削除され、一覧（`/recipes`）に遷移する
- [ ] 削除後、一覧にそのレシピのタイトルが表示されない
- [ ] 削除後、同じ詳細 URL を開くと「見つかりません」画面になる
- [ ] 確認ダイアログで「キャンセル」を選ぶと詳細に留まり、内容は変わらない
- [ ] 未ログインで詳細 URL を開くとログイン画面にリダイレクトされる
- [ ] 他ユーザーのレシピ ID を開くと「見つかりません」になり、削除ボタンは出ない
- [ ] 編集画面に削除ボタンは無い（§4）
- [ ] 一覧行に削除ボタンは無い（§4）
- [ ] 削除に失敗したとき、詳細画面にエラーが見え、真っ白や無限ロードにならない
- [ ] 権限不足などで削除できないとき、「見つかりません」と誤認しないエラーが見える
- [ ] 存在しない ID・不正な形式の ID の詳細 URL でも「見つかりません」になり、削除ボタンは出ない
- [ ] 確認ダイアログに「本当に削除しますか？」と分かる文言がある
- [ ] 「削除」ボタンは危険操作として赤系の枠線ボタンで、「編集」の近くに置かれている
- [ ] モバイル幅（375px 相当）で横スクロールなしに削除操作できる
- [ ] 一覧の検索・絞り込み・ソート・ページネーション、追加、編集、既存の詳細表示が従来どおり動く（回帰）

### 確認メモ（環境・範囲）

- 確認環境: ローカル（L2・エージェント） / Preview（L4・人間）
- 端末: モバイル幅も見る
- 回帰で触る画面: レシピ一覧（`/recipes`）、レシピ詳細（`/recipes/[id]`）、レシピ編集（`/recipes/[id]/edit`）、レシピ追加（`/recipes/new`）、ログイン（`/login`）
- その他メモ:
  - サインアップ画面が無いため、L4 前に確認済みユーザー（A/B）を用意する
  - **L4 の前に必須:** Preview が使うホスト側 Supabase に migration `20260812000000_add_recipes_delete_policy.sql`（DELETE policy + grant）を適用する。未適用だと確認ダイアログまで開けるが削除実行時に失敗する
  - L4 では「詳細→削除→確認→一覧から消える」「キャンセルで詳細に留まる」「削除後に詳細 URL が見つからない」「他ユーザー詳細 URL」「未ログイン」を必ず通す
  - 他ユーザー非表示: ユーザーAのレシピをユーザーBで開く → 見つからない。Aが削除したレシピがBの一覧に影響しないこと
- L4 用の補助データ: [`supabase/qa/l4_recipe_delete_seed.sql`](../../../supabase/qa/l4_recipe_delete_seed.sql) / [`l4_recipe_delete_cleanup.sql`](../../../supabase/qa/l4_recipe_delete_cleanup.sql)。タイトル接頭辞は `【L4-Delete`

## 7. 空・エラー・例外（任意）

| 場面 | 期待する見え方・挙動 |
| --- | --- |
| 削除に失敗（通信・DB エラー） | 詳細画面にエラーメッセージ。真っ白・無限ロードにしない |
| DELETE RLS/grant 未適用 | 削除実行時に権限エラーが分かるメッセージ（「見つかりません」と誤認しない） |
| 未ログイン | ログイン画面へリダイレクト |
| 削除後にブラウザバック | 削除済み詳細の内容は表示されない（一覧に戻る、または詳細 URL なら「見つかりません」） |
| 他ユーザー・存在しない・不正 ID | 詳細と同じ「レシピが見つかりません」画面。削除ボタンは出ない |
